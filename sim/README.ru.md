# Симулятор адаптера

[English version](README.md)

Изображает адаптер (XIAO ESP32-C5) с подключённой Citroën C3 II, чтобы писать и проверять приложение без железа и без машины.
Говорит по протоколу [DOCS/ПРОТОКОЛ.md](../DOCS/ПРОТОКОЛ.md).

## Запуск

```sh
python -m pip install -r sim/requirements.txt
python sim/c3_sim.py
```

Слушает `ws://0.0.0.0:8765`. В приложении в настройках указать `ws://<IP компьютера>:8765`
(телефон и компьютер в одной Wi-Fi сети; Windows может спросить про брандмауэр — разрешить для частной сети).

Параметры:

| | |
|---|---|
| `--port 8765` | порт |
| `--engine-off` | зажигание есть, мотор не крутится (АКБ 12,6 В) |

## Что умеет

- Шина B (OBD 3/8), KWP2000 по-PSA, как на настоящей C3 II (AEE2004): BSI `752/652` (сеанс `10 C0`), двигатель Valeo V46 `6A8/688` (сеанс `81`), ABS/ESP ESPMK100 `6AD/68D`, подушки Autoliv `744/644`, щиток `75F/65F`.
  Модели блоков, адреса, номера деталей и раскладка данных — из базы знаний приложения (`app/assets/kb/c3_ii.json`, собрана из PSA-RE); значения — от «машины» (обороты, температура, АКБ…).
  Опознание (`21 80` / `21 FE`) с номером детали настоящего варианта C3 II — приложение узнаёт модель; VIN (`21 B0`); записи данных (`21 xx`); ошибки (`17 FF 00`: у BSI две, у двигателя P0130 есть сейчас и P0300 сохранена); сброс (`14 FF 00`).
- Каждое новое подключение — с чистого листа, как после включения: шины закрыты, ошибки у блоков на месте, сеансы закрыты.
- Без открытого сеанса блоки отказывают (`7F xx 80`), а сеанс гаснет через 5 с без запросов — так проверяется, что приложение его держит.
- Запись и доступ по ключу не даёт: отвечает отказом, как блок без доступа (`7F xx 33`). Приложение и так только читает.
- Шина A (OBD 6/14): обычный OBD-II `7DF/7E8`, режимы `01` (обороты, температура, дроссель, напряжение), `03`, `04`, `09 02` (VIN).
- Монитор шины (`summary`): кадры BSI-шины раз в 250 мс, напряжение раз в секунду.
- Стоп-кадры: OBD-II режим `02`. У KWP-блоков PSA стоп-кадров `19 04` нет.
- Ещё два блока, которых нет в базе знаний (`6B1/691`, `77A/67A`, UDS), — на них проверяется «поиск блоков».
  Адреса выдуманные, только для проверки.
- В ответе на `isotp.req` всегда есть `rx`; `rx: "*"` — «прими ответ с любого адреса» (поиск блоков).

Номера деталей взяты из вариантов C3 II в PSA-RE; те ли блоки стоят на настоящей машине, покажет первый скан.

## Проверка

```sh
python sim/test_client.py                       # симулятор на этом ПК
python sim/test_client.py ws://192.168.4.1:81/ws  # потом — настоящий адаптер
```
