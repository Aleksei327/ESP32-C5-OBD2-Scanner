# Симулятор адаптера

[English version](README.md)

Изображает адаптер (XIAO ESP32-C5) с подключённой Citroën C3 II, чтобы писать и проверять приложение без железа и без машины.
Говорит по протоколу [DOCS/ПРОТОКОЛ.md](../DOCS/ПРОТОКОЛ.md).

## Запуск

```sh
python -m pip install -r sim/requirements.txt
python sim/c3_sim.py
```

Слушает `ws://0.0.0.0:8765`. В приложении в настройках указать `ws://<IP компьютера>:8765`
(телефон и компьютер в одной Wi-Fi сети; Windows может спросить про брандмауэр — разрешить для частной сети).

Параметры:

| | |
|---|---|
| `--port 8765` | порт |
| `--engine-off` | зажигание есть, мотор не крутится (АКБ 12,6 В) |

## Что умеет

- Шина B (OBD 3/8), UDS: BSI `752/652`, двигатель `6A8/688`, ABS `6AD/68D`, подушки `744/644`, щиток `75F/65F`.
  VIN, номера, ошибки (BSI: U0100, U0155; двигатель: P0130, P0300), живые данные двигателя, 5 настроек BSI (только чтение).
- Запись настроек не даёт: отвечает отказом, как блок без доступа. Приложение сейчас только читает.
- Шина A (OBD 6/14): обычный OBD-II `7DF/7E8`, режимы `01` (обороты, температура, дроссель, напряжение), `03`, `04`, `09 02` (VIN).
- Монитор шины (`summary`): кадры BSI-шины раз в 250 мс, напряжение раз в секунду.
- Стоп-кадры ошибок (`19 04`): условия в момент появления ошибки у BSI и двигателя; OBD-II режим `02`.
- Ещё два блока, которых нет в базе знаний (`76D/66D`, `6B5/5B5`), — на них проверяется «поиск блоков».
  Адреса выдуманные, только для проверки.
- В ответе на `isotp.req` всегда есть `rx`; `rx: "*"` — «прими ответ с любого адреса» (поиск блоков).

Все DID живых данных и настроек — выдуманные: настоящие появятся в базе знаний, когда послушаем машину.

## Проверка

```sh
python sim/test_client.py                       # симулятор на этом ПК
python sim/test_client.py ws://192.168.4.1:81/ws  # потом — настоящий адаптер
```
