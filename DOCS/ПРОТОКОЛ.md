# Протокол адаптер ↔ приложение (v0)

[English version](en/protocol.md)

Адаптер — «тупой» транспорт. Он не знает марок машин, не знает, что такое VIN или ошибка.
Он умеет: открыть шину CAN, отправить запрос блоку и вернуть ответ, держать сессию, слушать шину, мерить напряжение.
Вся логика (что спросить и как расшифровать) — в приложении и его базе знаний.

Так прошивку не надо менять под каждую машину, а новая машина — это новый JSON-файл в телефоне.

## Транспорт

- Wi-Fi: адаптер поднимает точку доступа `SCANER-C5-XXXX` (XXXX — конец MAC-адреса) с паролем WPA2, адрес `ws://192.168.4.1:81/ws`. Пароль случайный, создаётся при первом включении и хранится в адаптере; узнать и сменить — командой `wifi` в консоли по USB.
- Симулятор на ПК: `ws://<IP компьютера>:8765` (см. `sim/README.md`).
- Позже BLE — те же JSON-сообщения.

Каждое сообщение — один JSON-объект в одном текстовом кадре WebSocket.

## Запрос → ответ

Приложение шлёт `{"id": 7, "cmd": "...", ...}`, адаптер отвечает с тем же `id`:

```json
{"id": 7, "ok": true, ...}
{"id": 7, "ok": false, "err": "timeout"}
```

Байты везде — HEX-строкой без пробелов (`"22F190"`), CAN ID — HEX-строкой (`"752"`).

| cmd | Параметры | Ответ | Что делает |
|---|---|---|---|
| `hello` | — | `fw`, `hw`, `buses`, `mv` | Знакомство: версия прошивки, список шин, напряжение |
| `vbat` | — | `mv` | Напряжение на OBD 16, мВ |
| `bus.open` | `bus` (`A`/`B`), `bitrate`, `listen` | — | Открыть шину. `listen: true` — только слушать (передатчик выключен) |
| `bus.close` | `bus` | — | Закрыть шину |
| `isotp.req` | `bus`, `tx`, `rx`, `data`, `timeout_ms` | `data`, `rx` | Отправить запрос блоку (ISO-TP), дождаться ответа. «Подождите» (7F xx 78) адаптер пережидает сам. `rx: "*"` — адрес ответа неизвестен: принять первый ответ после запроса и вернуть, с какого `rx` он пришёл (нужно для поиска блоков: у PSA бывает и 752→652, и 6A8→688) |
| `tester.start` | `bus`, `tx`, `data`, `period_ms` | — | Держать сессию: слать `data` (обычно `3E80`) каждые `period_ms` |
| `tester.stop` | `bus`, `tx` | — | Перестать |
| `monitor.start` | `bus`, `mode` (`summary`/`raw`), `ids` (необязательно) | — | Слушать шину и присылать события |
| `monitor.stop` | `bus` | — | Перестать слушать |

Ответ блока возвращается как есть — в том числе отказ (`7F 22 31` и т.п.). Расшифровывает приложение.

Команды одной шины адаптер выполняет по очереди, в порядке прихода; шины A и B работают независимо.

### Кадры ISO-TP

- Шина A (OBD-II): кадры добиваются до 8 байт нулями, как требует ISO 15765-4. «Присылай остальное» от адаптера — `30 00 00`.
- Шина B (PSA): кадр такой длины, сколько в нём данных, без добивки — так шлют диагностические программы PSA. «Присылай остальное» — `30 00 05` (5 мс между кадрами, как у ludwig-v/arduino-psa-diag).
- В `isotp.req` можно передать `pad: true/false`, чтобы поменять это для одного запроса.
- `rx: "*"`: ответом считается первый кадр с ID 600–7FF, который начинается с `sid + 40` или `7F sid`. После него адаптер слушает только этот ID.

### Ошибки

| `err` | Значит |
|---|---|
| `bad_args` | Не хватает или кривые параметры |
| `bus_closed` | Шина не открыта |
| `listen_only` | Шина открыта только на прослушку, передавать нельзя |
| `timeout` | Блок не ответил |
| `bus_off` | Шина в аварии (замыкание, нет терминатора, не та скорость) |
| `busy` | Очередь команд этой шины переполнена (больше 16 ждут выполнения) |

## События (без `id`)

```json
{"ev": "vbat", "mv": 12610}
{"ev": "frames", "bus": "B", "t": 123456, "frames": [{"id": "0B6", "data": "0000000000000D0", "n": 9640, "hz": 20}]}
{"ev": "frame", "bus": "B", "t_us": 123456789, "id": "0B6", "data": "00000000000000D0"}
{"ev": "bus", "bus": "B", "state": "bus_off"}
```

- `vbat` — раз в секунду.
- `frames` — режим `summary`: раз в 250 мс по последнему кадру каждого ID со счётчиком и частотой. Для экрана «Монитор шины».
- `frame` — режим `raw`: каждый кадр. Для записи лога, лучше с фильтром `ids`.

## Безопасность

- После включения обе шины закрыты, приёмопередатчики в режиме «только слушать» (Rs = 1).
- Передавать можно только после `bus.open` с `listen: false`. Приложение делает это, только когда пользователь начал диагностику.
- Приложение сейчас только читает: блоки, ошибки (и их сброс), живые данные, монитор шины. Записи в блоки нет.
- Приложение отключилось (закрылось соединение или телефон ушёл из сети Wi-Fi) — адаптер останавливает «я здесь» и монитор и закрывает обе шины.

## Что поверх (в приложении)

Приложение говорит с блоками на двух языках поверх одного и того же ISO-TP — адаптеру разницы нет:

- **KWP2000 по-PSA** — большинство блоков AEE2004, в том числе почти все на C3 II: сеанс `81` (блоки шины IS: двигатель, ABS…) или `10 C0` (BSI и блоки салона), чтение записей `21 xx`, ошибки `17 FF 00` (ответ `57 <число> {код(2) состояние}`), сброс `14 FF 00`, «я здесь» `3E`. Сеанс гаснет через несколько секунд без запросов — приложение переоткрывает его само.
- **UDS** (ISO 14229) — новые блоки: `10` сессия, `22` чтение, `19` ошибки и стоп-кадры, `14` сброс, `3E 00` «я здесь».

На каком языке говорит блок, приложение узнаёт само (пробует сеанс KWP, потом `3E 00`), а модель блока — по номеру детали из ответа на команду опознания. Всё это лежит в базе знаний (`app/assets/kb/c3_ii.json`, собирается из [PSA-RE](https://github.com/prototux/PSA-RE) скриптом `app/tool/build_kb.py`).

На шине A (OBD 6/14) — обычный OBD-II: `7DF`/`7E8`, режимы `01`, `03`, `04`, `09`.
