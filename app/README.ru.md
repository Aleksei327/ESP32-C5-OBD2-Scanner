# Приложение OBD Scanner

[English version](README.md)

Приложение на Flutter для Android (делали под Galaxy A55). С адаптером говорит по Wi-Fi: JSON по WebSocket, см. [протокол](../DOCS/ПРОТОКОЛ.md). Адаптер — «тупой» транспорт, всё, что зависит от машины, живёт здесь и в базе знаний.

**Только чтение:** поиск и опрос блоков, опознание модели блока по номеру детали, идентификация (VIN, номера деталей и ПО), ошибки с расшифровкой — чтение и сброс (стоп-кадры у блоков на UDS), живые данные и настройки (только посмотреть), стрелочные датчики OBD-II с графиками и записью в CSV, монитор шины CAN, отчёт в PDF. В блоки ничего не пишется, кроме сброса ошибок.

Ещё: гараж машин по VIN, до 5 фото на машину, две темы (тёмная инженерная и яркая светлая), русский и английский.

Сканы сохраняются в телефоне, по 10 последних на машину. Вкладка «Блоки» показывает последний (или любой из истории) и сама скан не запускает: новый автоскан — его кнопкой, а один блок можно пересканировать с его экрана. Пересканирование блока или сброс его ошибок добавляют в историю новую запись, так что видно, что было до и после. Гараж и сохранённые сканы открываются и без адаптера; живым данным, датчикам и монитору шины он нужен. Тексты ошибок в скане не хранятся, а подставляются при показе, поэтому новые переводы видны и в старых сканах.

## Сборка и запуск

Нужны Flutter 3.44 (Dart 3.12) и Android SDK.

```sh
cd app
flutter pub get        # заодно генерирует lib/l10n/gen из файлов .arb
flutter run            # телефон по USB
```

Подключение: адаптер раздаёт Wi-Fi `SCANER-C5-XXXX` (имя и пароль — команда `wifi` в его консоли), адрес `ws://192.168.4.1:81/ws`, или [симулятор](../sim/README.ru.md) по `ws://<IP компьютера>:8765`. К сети адаптера приложение подключается само: на экране подключения — имя сети и пароль. Такая сеть служит только приложению, интернет телефона остаётся на мобильных данных. Если подключить телефон к сети адаптера в настройках Wi-Fi, Samsung делает её основной для всего телефона, и интернет пропадает у всех приложений.

Тесты:

```sh
flutter test                                   # обычные тесты
python ../sim/c3_sim.py                        # в соседнем окне
flutter test --tags sim --run-skipped          # проверка вместе с симулятором
```

## Что где

| Путь | Что там |
| --- | --- |
| `lib/transport/` | клиент WebSocket; KWP2000 по-PSA и UDS (`diag.dart`), OBD-II (`obd.dart`) |
| `lib/state/` | состояние приложения, диагностика (узнаёт протокол и модель блока, держит сеанс KWP), гараж, фото машин, сохранённые сканы |
| `lib/kb/` | модель базы знаний, разбор значений по битам в нотации PSA-RE, список датчиков OBD-II |
| `lib/ui/` | экраны: машина, блоки, блок, датчики, монитор шины, гараж, настройки, отчёт |
| `lib/l10n/` | переводы (`app_ru.arb`, `app_en.arb`) |
| `assets/kb/c3_ii.json` | база знаний по C3 II (PSA AEE2004), собрана из [PSA-RE](https://github.com/prototux/PSA-RE) — руками не править; рядом `PSA-RE-LICENCE.txt` |
| `assets/kb/c3_ii_dtc_gpl.json` | дополнительные тексты ошибок из [ludwig-v/arduino-psa-diag](https://github.com/ludwig-v/arduino-psa-diag), GPL-3.0 (рядом `GPL-3.0.txt`); тоже собирается скриптом |
| `assets/google_fonts/` | шрифты Exo 2 и IBM Plex с текстами лицензии OFL |
| `tool/` | `build_kb.py` + `kb_ru.json` (база знаний и её русские тексты), `build_psa_codes.py` (локальный список кодов PSA, см. ниже), скрипты, которые рисуют иконку приложения |

## База знаний

`assets/kb/c3_ii.json` собирается из проекта PSA-RE (Apache-2.0) закреплённой версии: все блоки, которые бывают на C3 II (код A51), их возможные модели с протоколом, сеансом, командой опознания и известными номерами деталей, записи данных (живые данные, идентификация, настройки) с раскладкой по битам и тексты ошибок. Процедуры, проверка исполнителей и всё, что пишет в блоки, не берётся.

```sh
python -m pip install pyyaml
python tool/build_kb.py       # из app/; PSA-RE скачивается один раз в tool/.cache/
```

Если у кода ошибки нет текста, скрипт берёт его ещё из двух источников: списки PSA от ludwig-v (GPL-3.0, поэтому они лежат отдельным файлом `c3_ii_dtc_gpl.json`) и общие тексты SAE J2012 из [OBD Codes List](https://obdcodeslist.com/code-data.html). Приложение ищет текст по порядку: опознанная модель блока, любая модель этого места, файл ludwig-v, локальный список кодов PSA (ниже), общий текст SAE. Общий текст берётся только для кодов, смысл которых задаёт сам стандарт (P0, P2, P34–P39, B0, C0, U0): в диапазонах производителя и в U3, куда PSA пишет свои коды BSI, он был бы неверным. В приложении он помечен «общее описание SAE».

**Список кодов PSA (только локально).** На KWP код ошибки PSA — два байта: первая шестнадцатеричная цифра — вид неисправности (7 удалённая, 8 нет сигнала, 9 неправдоподобное значение, A замыкание на плюс, B замыкание на массу, C обрыв цепи, D/E ниже/выше допустимого, F без уточнения), остальные три — номер, и у каждого блока свой диапазон номеров (BSI 0x400–0x5FF, климат 0x700–0x7FF…). Приложение показывает сырой код рядом с кодом в стиле SAE (`B24C0  PSA A4C0`). Тексты можно взять из заводского списка кодов PSA, но этот документ копировать нельзя, поэтому ни его, ни взятого из него в репозитории нет. Если у вас есть копия: `python tool/build_psa_codes.py <список.pdf> export` выгружает непереведённое пачками в `tool/.cache/psa_tr/`, `merge` забирает переведённые пачки в `tool/.cache/psa_tr.json` (переводы хранятся по исходному тексту, поэтому изменения в разборе PDF их не теряют), а `python tool/build_psa_codes.py <список.pdf>` собирает `assets/kb/psa_codes.json` с русскими и английскими текстами. Для стандартных P-кодов русское название берётся из общих текстов SAE базы знаний. Всё это в .gitignore. Без этого файла приложение работает как раньше. Если номера нет в списке, приложение всё равно называет диапазон блока и вид неисправности.

Русские тексты — из `tool/kb_ru.json` (английский текст → русский); что ещё не переведено, скрипт пишет в `tool/.cache/untranslated.txt`. Общие тексты SAE построены по шаблону («Fuel Temperature Sensor B Circuit Low»), поэтому переводятся по частям: `sae_parts` (узел) и `sae_faults` (вид неисправности), фразу собирает `tool/sae_ru.py`. `tool/kb_translate.py export` выгружает непереведённое пачками в `tool/.cache/tr/`, `merge` забирает переведённые пачки обратно в `kb_ru.json`.
